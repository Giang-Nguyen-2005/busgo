# BusGo V1.5 — 10–15 minute demo

All people/operators and all money movements are fictional. Say “thanh toán mô
phỏng / hoàn tiền mô phỏng”; never ask the audience to transfer money. Share links
manually; BusGo does not integrate Zalo. Display time is Vietnam time.

## Prepare once, rehearse before presenting

Follow [deployment/startup](deployment.md). Use `dev,demo` against a dedicated
schema, verify health plus tomorrow's HCM -> Đà Lạt search, and retain this database.
Same-day restart creates no duplicate seed trips. Record your chosen trip, booking
codes and maintenance title in local rehearsal notes; never reset SQL to rehearse.

For the quickest rehearsal prepare three independent future reservations on an An
Phú trip more than six hours away: one WEB paid booking for customer cancellation,
one PHONE PAY_ON_BOARD for collection/boarding, one unpaid PHONE PAY_ON_BOARD for
no-show. A fourth PHONE QR booking demonstrates anonymous payment. Use separate
seats. Seed crew covers newly created eligible An Phú trips; confirm a valid driver
in the trip workspace. Keep a spare available bus without trips for maintenance.

## Recovery and acceptance

If a request fails, use retry and read the message; do not treat a failed request
as zero activity. If booking creation timed out, inspect history before another
attempt. Hold expiry returns to seat selection. Replaced payment links are invalid;
cancelled/expired reservations cannot be paid. Existing history is preserved.

Check 390/820/1440 widths before the demo: local table scrolling, legible identities,
accessible action names, keyboard-visible focus, cancellation dialog Tab/Escape,
no page overflow and no browser exceptions. A non-Vietnam browser must still show
Vietnam departure/maintenance times. Log out between accounts; no prior customer
or operator data should remain. See [verification](m19-verification.md) for actual
automated evidence and remaining limitations.
